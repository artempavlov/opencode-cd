# Cross-Project Session Migration

Спецификация расширения `opencode-cd`, которое переносит текущую сессию
OpenCode в другую существующую директорию, включая директорию другого
Git-проекта.

## 1. Краткое описание проблемы

Штатный OpenCode API `experimental.controlPlane.moveSession` разрешает менять
директорию только внутри того же `projectID`. При переходе в другой
Git-репозиторий OpenCode выдаёт `DestinationProjectMismatchError`.

Нужен UI-плагин, который:

- принимает любую существующую директорию;
- переносит туда полную историю выбранной сессии;
- создаёт новую внутреннюю запись сессии;
- переключает TUI на новую запись;
- удаляет исходную сессию только после проверки результата;
- не переносит незакоммиченные изменения исходного проекта.

## 2. Цели и нецели

### Цели

- Перенос между разными Git-репозиториями.
- Перенос в директорию без Git.
- Сохранение всей переписки и `parts`.
- Сохранение модели и агента с автоматической заменой недоступных.
- Применение конфигурации проекта назначения.
- Использование permission-правил проекта назначения.
- Атомарное поведение с очисткой частичных результатов.

### Нецели

- Сохранение undo/redo и snapshots исходного проекта.
- Перенос незакоммиченных файлов.
- Перенос несвязанных с выбранной сессией записей; дочерние subagent-сессии
  выбранного дерева переносятся автоматически.
- Копирование файлов, упомянутых во вложениях или старых tool parts.
- Обязательное сохранение исходного `sessionID` - новый ID допустим.

## 3. Пользовательский сценарий

1. Пользователь находится внутри активной сессии.
2. Вызывает `Ctrl+Shift+D`, `/session-cd` или команду из command palette.
3. Указывает существующую директорию назначения.
4. Плагин определяет проект назначения:
   - корень Git-репозитория, если директория находится в Git;
   - non-Git/global context, если Git отсутствует.
5. Плагин проверяет, что сессия не занята.
6. Пользователь подтверждает перенос переписки в новый проект.
7. Плагин находит дерево дочерних subagent-сессий и проверяет их состояние.
8. Плагин экспортирует каждую сессию во временный защищённый JSON.
9. В проекте назначения создаются новые сессии с соответствующими parent-связями.
10. В них импортируются история, сообщения и parts.
11. Проверяются директория, проект, количество сообщений и возможность
    продолжения.
12. В новые сессии добавляются синтетические напоминания о новой директории.
13. Исходное дерево сессий удаляется после успешной проверки.
14. TUI автоматически открывает новую корневую сессию назначения.

При любой ошибке до пункта 12 исходная сессия остаётся нетронутой.

## 4. Функциональные требования

1. Плагин MUST принимать любую существующую директорию, включая директории
   без Git.
2. Плагин MUST считать указанную поддиректорию точной `session.directory`.
3. Если директория находится в Git-репозитории, проектом назначения MUST
   считаться корень этого репозитория.
4. Плагин MUST создавать новую запись сессии с новым `sessionID`.
5. Плагин MUST переносить всю доступную историю сообщений и parts без
   изменения текста и порядка.
6. Плагин MUST сохранять title, metadata, модель и агента, если они доступны.
7. Если модель недоступна в проекте назначения, плагин MUST сначала выбрать
   effective default model из объединённой конфигурации назначения, а при её
   недоступности - другую доступную модель. Если агент недоступен, плагин MUST
   выбрать доступный агент. Каждая замена MUST сопровождаться предупреждением.
8. Permission-правила исходной сессии MUST NOT переноситься; должны
   использоваться правила назначения.
9. `parentID` MUST быть очищен у корневой перенесённой сессии, если её родитель
   остаётся в исходном проекте; у автоматически перенесённых детей `parentID`
   MUST ссылаться на новую родительскую сессию.
10. Лексикографический порядок новых `sessionID` дочерних сессий одного родителя
    MUST соответствовать порядку их исходных `sessionID`, который TUI использует
    для переключения между subagent-сессиями.
11. Незакоммиченные изменения исходного проекта MUST оставаться на месте.
12. Плагин MUST запрещать перенос активной сессии во время работы модели, tool
    или subagent.
13. Плагин MUST проверять существование и доступность директории до начала
    миграции.
14. Плагин MUST удалять частично созданную сессию назначения при ошибке
    импорта.
15. Исходная сессия MUST удаляться только после успешной проверки новой.
16. При ошибке удаления исходной сессии новая сессия MUST сохраняться, а
    пользователь MUST получить предупреждение о наличии двух записей.
17. После успеха TUI MUST открыть сессию назначения.
18. Вложения, ссылки на файлы и старые tool parts MUST сохраняться как
    исторические данные без переписывания путей.
19. Временный экспорт MUST удаляться после успешного завершения или отката.

## 5. Нефункциональные требования

- Перенос не должен вызывать реальный LLM-запрос и не должен расходовать
  токены.
- В процессе должны отображаться состояния: экспорт, импорт, проверка,
  очистка.
- Повторный запуск во время активного переноса должен блокироваться.
- Временный файл должен создаваться с правами только для текущего пользователя.
- Ошибка должна быть понятна пользователю и содержать этап, на котором
  произошёл сбой.
- Плагин должен работать с OpenCode `1.18.x`.
- TUI-плагин не должен использовать JSX в npm/GitHub-установке: OpenCode
  загружает такие плагины под `node_modules`, где есть известная проблема с
  OpenTUI runtime.

## 6. Технические ограничения

- `controlPlane.moveSession` нельзя использовать для перехода между разными
  `projectID`.
- Публичный SDK OpenCode не предоставляет полноценный API для вставки
  исторических assistant/tool messages вручную.
- Штатный `opencode import` уже умеет:
  - переопределять `projectID` проектом текущей директории;
  - устанавливать новую `directory`;
  - вычислять новый relative path;
  - вставлять сообщения и parts в локальное хранилище.
- Поэтому миграцию лучше реализовать через временный export JSON и запуск
  `opencode import` с `cwd` проекта назначения.
- Для получения нового валидного `sessionID` можно временно создать сессию
  назначения через SDK, получить её ID, удалить заготовку и затем импортировать
  JSON с этим ID.
- Проект определяется OpenCode через Git remote/cache/root commit; для non-Git
  используется `global`.
- Источник плагина должен оставаться GitHub-репозиторием, например через
  `git+https://github.com/artempavlov/opencode-cd.git#main`.

## 7. Граничные случаи

- Директория не существует - отказ без изменения исходной сессии.
- Указана текущая директория - no-op.
- Директория назначения является поддиректорией другого Git-репозитория -
  перенос разрешается.
- Директория назначения без Git - перенос разрешается.
- Сессия занята - перенос блокируется.
- Исходная модель недоступна - выбрать effective default model назначения, а
  если она тоже недоступна, выбрать другую доступную модель.
- Нет доступного агента - выбрать доступного агента назначения.
- Сессия является дочерней - она переносится вместе с дочерним деревом, а
  `parentID` перепривязывается к новой родительской сессии.
- Есть незакоммиченные изменения - они остаются в источнике.
- Импорт оборвался - частичная сессия назначения удаляется.
- Проверка истории не прошла - источник сохраняется, назначение удаляется.
- Удаление источника не прошло - обе сессии сохраняются, пользователь получает
  предупреждение.
- Перенос запущен повторно - второй запуск блокируется.
- В истории есть старые пути файлов - они не переписываются.

## 8. Риски и компромиссы

- **Импорт через CLI зависит от реализации OpenCode.**
  Митигировать проверкой версии OpenCode и тестом CLI перед началом миграции.

- **Import не является полноценной транзакцией.**
  Митигировать временным ID, проверкой результата и удалением частичной записи.

- **Новый `sessionID` ломает внешние ссылки на старую сессию.**
  Это принятое следствие выбранной модели переноса; пользователь согласился на
  новую запись.

- **Перенос без snapshots очищает undo-историю.**
  Это принятое поведение, потому что snapshots привязаны к исходному проекту.

- **При ошибке удаления могут временно существовать две сессии.**
  Не удалять проверенную новую сессию, чтобы не рисковать потерей истории.

- **Проектная конфигурация может изменить поведение продолжения.**
  Сохранять модель и агента, но использовать инструкции и permission-правила
  назначения.

## 9. План реализации

1. Добавить в плагин отдельную ветку для cross-project migration.
2. Оставить штатный `moveSession` для перемещений внутри одного проекта.
3. Добавить проверку idle-состояния сессии.
4. Получить информацию об исходной сессии и её сообщениях.
5. Определить проект и точную директорию назначения.
6. Создать временный export-файл с ограниченными правами.
7. Получить новый валидный `sessionID` через временную сессию назначения.
8. Удалить временную заготовку.
9. Переписать в export:
   - новый `sessionID`;
    - `parentID: undefined` для корня и новые `parentID` для автоматически
      перенесённых детей;
   - permission-поле;
   - модель и агента при необходимости.
10. Запустить `opencode import` из директории назначения.
11. Проверить:
    - project ID;
    - directory;
    - title;
    - model/agent;
    - порядок и количество сообщений;
    - количество parts;
    - возможность принять synthetic no-reply prompt.
12. Удалить исходную сессию.
13. Открыть новую сессию в TUI.
14. Удалить временный файл.
15. Добавить regression-тесты для same-project, cross-project, non-Git и
    partial-failure сценариев.
16. Обновить README и проверить установку из GitHub.

## 10. Критерии приёмки

- Given активная idle-сессия в Git-репозитории A, when указана директория
  Git-репозитория B, then создаётся сессия в B с полной историей.
- Новая сессия имеет проект B и точную указанную директорию.
- Исходная сессия удаляется после проверки.
- Незакоммиченные изменения в A остаются в A.
- Модель и агент сохраняются; недоступная модель заменяется effective default
  model назначения либо другой доступной моделью, а недоступный агент -
  доступным агентом.
- Порядок переключения между дочерними subagent-сессиями сохраняется.
- Permission-правила берутся из B.
- Дочерняя сессия после переноса не содержит parent-ссылку на A.
- Given директория без Git, when она существует, then перенос разрешается.
- Given активный tool/model run, when пользователь запускает перенос, then
  операция отклоняется без изменений.
- Given ошибка импорта, then исходная сессия остаётся, а частичная запись
  назначения удаляется.
- Given ошибка удаления исходной сессии, then новая сессия сохраняется и
  показывается предупреждение.
- После успеха TUI открывает сессию назначения.
- GitHub-установка загружает TUI-плагин и регистрирует `/session-cd`.
- `bun run typecheck` проходит.
